# cement spec

## Intent

Cement turns repeated LLM work into narrowly scoped deterministic functions. In a chat deployment such as Open WebUI, users request one kind of task many times with slight variations. An OCR extraction is an example: the documents differ, and the requests differ slightly. The LLM answers each request, often with a small script. Cement keeps the requests and the answers in the background. Periodically, an LLM-driven learning pass reads those transcripts and finds the requests that recur. It combines their slightly different scripts into one deterministic function that covers every case it has seen. The function is regular, and it can be large. It grows as new variations appear, and it keeps each case exact. A person can read the function and decides whether to switch it on or off in production. A function that is on follows each new version that learning produces, or it stays pinned to one version. The person can roll back to any earlier version. While the function is on, it answers the matching requests instead of the LLM, so the results stop depending on probabilistic processing. Requests that the function does not cover still go to the LLM. A case is one exact key. Some requests differ in their values but share one structure, such as one form layout. For these, a verified projection maps each new input to its key. An input that the projection does not recognize goes to the LLM. Learning never widens a key beyond the inputs that it has seen.

The production artifact is a library and a CLI control plane that an interface like Open WebUI calls. The learning pass ships with it as a skill that the operator runs. The production artifact is not a web UI. The prototype artifact is a web UI demo. It shows the purpose, the situations that Cement serves, the output to expect, and how that output makes processes more efficient and more predictable.
