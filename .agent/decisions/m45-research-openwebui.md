## Notes

- **N1 — contract wording needs MAIN's ruling, not a spec edit by this research task.** `.agent/spec.md:5`: "matching requests are answered by the function instead of the LLM, so results stop depending on probabilistic processing"; line 21: "Cement functions as a tool the chat model calls + a filter that retains answers for the learning pass." R5 primary evidence shows native tools return to an LLM final-answer step. Inference: the owner-picked Tool+Filter design guarantees a deterministic **tool result**, not automatically the final reply or routing choice. Contract should distinguish those surfaces and verify any exact-rendering mechanism explicitly. No request to replace the owner's chosen architecture.
- **N2 — retained-answer binding.** R4 source preserves native call/result items under final assistant `output`; retain them alongside user/final text when available. Inference: operation + canonical input must come from structured tool arguments or a deliberate capture protocol, not a guess from prose. Avoid counting a Cement-hit result as new independent LLM evidence; retries/regeneration need a stable provenance/dedup rule. These are contract recommendations, not claims that Open WebUI or current Cement already enforces them.
- **N3 — smoke scope.** R8 recipe is source-derived, not executed. No Open WebUI install, service launch, local HTTP request, account change or remote mutation performed. Existing port 8080 was never queried. Native tool execution requires the saved-chat streaming path described there; a plain API text reply plus successful outlet is insufficient evidence. Keep an end-to-end UI check separate from API/library checks; native stock display wording is version-dependent (R3).
- **N4 — skill shipment.** Keep shared workflow in the standard skill directory; host-specific discovery/explicit-invocation settings are thin adapters. Claude `disable-model-invocation` and Codex `agents/openai.yaml` policy are host extensions, not universal Agent Skills fields (R9–R10). The skill body should require an operator-initiated learning pass even on clients whose explicit-only setting has not been tested. A skill teaches an agent a workflow; it is not itself a scheduler or a substitute for deterministic CLI validation.
