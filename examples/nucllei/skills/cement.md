# Cement (学習済みの関数)

同じ種類の頼みが繰り返されると、Cement はモデルの答えを記録し、学習して決まった関数 (版) にする。
ユーザーが関数をオンにすると、その種類の頼みには関数の出力が答えになる (同じ入力には毎回同じ答え)。
関数が答えない頼みには、これまでどおり自分で答える。
台帳はユーザー本人の `/workspace/.cement/` にある。`run_shell` で `/ext/bin/cement` だけを使って扱い、`write_file`・`rm` などで直接触らない。

## 操作 (この配備で Cement が扱う頼み)

- `extraction_plan` — ユーザーが用紙 1 枚の全文を貼り、どの項目を抜き出すか・どこにあるかを聞く。
  - 入力: 貼られた用紙の全文。値も含めて 1 字も変えずに、下の手順で `write_file` の本文に入れる
  - 出力: 抽出の計画。患者の値は入れない:
    `{"fields": [{"name": "<snake_case の名前>", "label": "<コロンの前の文字>"} または {"name": "<名前>", "section": "<見出しの文字>"}]}`

## 流れ

1. 用紙の全文を `write_file` でファイルに書き、そのファイルで関数に引く (頼み 1 件につき 1 回)。
   path は `/workspace/.cement/in/` の下に、頼みごとに違う名前で置く (例: `/workspace/.cement/in/plan-1.txt`)。
   用紙をシェルのコマンドの中に書かない (用紙の行がコマンドとして動くことがある)。`use` は読んだファイルを消す:

   ```sh
   /ext/bin/cement use extraction_plan --field document --input-file /workspace/.cement/in/plan-1.txt
   ```

2. 出力の最後の `次の手:` に従う。
   - 「学習済みの関数が答えた」: `出力:` の JSON をそのまま使って返答を書く。中身を足したり直したりしない。`record` は流さない
   - 「学習済みの関数はこの頼みに答えない」: 自分で答えの出力 (上の形の JSON) を作り、返答を書く前に記録する。
     出力は用紙と同じく `write_file` でファイルに書く (例: `/workspace/.cement/in/answer-1.json`)。
     出力をシェルのコマンドの中に書かない。`record` は読んだファイルを消す。
     `--request` にはユーザーの頼みの文をそのまま入れる (文に `'` があれば `'\''` と書く):

     ```sh
     /ext/bin/cement record <控え> --request '<ユーザーの頼みの文>' --output-file /workspace/.cement/in/answer-1.json
     ```

     返答では、記録した出力と同じ内容を普段の返答の形 (表や箇条書き) で示す
   - `中止:` で止まったら、その `次の手:` に従う。Cement が使えないときは、Cement を使わずに普段どおり答える
3. `record` の `次の手:` が学習を求めたら、返答を書く前に `load_skill` で `cement-learn` を読み込み、その手順で学習を済ませる。
   返答の最後に、学習の結果を `cement-learn` の手順どおり 1〜2 行で添える

## 守ること

1. **関数をオン・オフしない** (`switch` を流さない)。オンにできるのはユーザーだけで、ユーザーが `/cement-switch` と送ったときに読み込まれる skill が扱う。
   オン・オフや中身を見たいと言われたら「`/cement-switch` と送ると、関数の状態を見てオン・オフできます」と返す
2. 用紙の全文は貼られたとおりに渡す (要約・整形・並べ替えをしない)。Cement は入力をそのまま比べる
3. 返答で Cement の仕組みを長く説明しない。関数が答えたときも、普段の返答と同じ形で書く
