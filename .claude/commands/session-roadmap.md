# Session roadmap

Continue project along the roadmap; run bare. Route a user-supplied task through `/session-prompt`. State arrives attached: @.agent/roadmap.md @.agent/memory.md. An unexpanded path ⇒ `ls .agent/`: stub the missing file (roadmap: goal + first UNPLANNED milestone from available context; memory: empty), read the present one. Run MODE for the active milestone = first awaiting DONE/REVIEWED. Session scope = one MODE run; a `kernel` unit spans the S1..S<k> sessions its budget names (measured 1-7 here), each ending on its own checkpoint or DONE commit. A PARKED milestone re-enters dispatch when its named precondition is met and its marker cleared.

MODE ← active-milestone status (state change ⇒ scoped commit; stable BLOCKED recheck ⇒ read-only close; convention below):
- UNPLANNED (incl. a still-unsplit future milestone) → PLANNING
- IN-PROGRESS (has an OPEN unit) → WORK-UNIT (lowest OPEN unit)
- IN-PROGRESS (OPEN=0; BLOCKED>0) → WORK-UNIT (lowest BLOCKED, gate recheck)
- IMPLEMENTED (all units DONE; adjudication open) → MILESTONE-REVIEW, re-entered until every row is adjudicated

Assurance splits by MAIN's cost (project `CLAUDE.md`): mechanical checks (red suite, `orc`, `diff`) + the OPEN unit's own contract attack, whose rows MAIN rules into that contract through an idempotent `--check` patcher = WORK-UNIT; review of MAIN's diff = MILESTONE-REVIEW, per unit in one parallel block, resumed across sessions ⇒ bounded adjudication per session, REVIEWED on a fully adjudicated check set.

Isolation — worktree mechanics per global `CLAUDE.md` `Subagents`; project bindings: one worktree per teammate at `.scratch/worktrees/<name>`, MAIN alone writing the primary tree, gate toolchain-env recipe → memory.
- Worktrees deliver evidence — suites, oracle bytes, matrices, probe results; the primary tree ships. MAIN reads `git diff --name-status main..wt/<name>` BEFORE choosing a merge verb: a worktree based at a pre-implementation SHA renders main's later commits as deletions, so `git merge --squash` there is a silent revert and the harvest is `git checkout wt/<name> -- <path>` proven byte-identical by sha256 (which stages the path — memory carries the `--amend` trap). `prod` harvest alone merges content: targeted files + a spot-check of the contract's invariant surfaces even on a clean validator run → one scoped commit.

Execution map — MAIN implements + rules; teammates prepare MAIN's decisions, absorb bulk reading, attack MAIN's product, and harden every ruling into a mechanical gate.
- Authorship split: judgment-bearing code (kernel/validator/spec/normative surfaces) = MAIN-authored in the primary tree, start to ship; mechanically-gated artifacts (validator-backed corpus/fixtures/goldens/tables) = teammate production. Teammate output enters through exactly three trust shapes: execution-verified (suites/scripts/repros MAIN reruns), attention-directing (maps/flags/findings MAIN validates before action; validation cost = attention), raw material (drafts/digests MAIN edits into shipped form).
- Assurance scales to the unit's declared tier (project `CLAUDE.md`): `kernel` = full wave battery below; `data` = `prod` alone behind one structural validator + live spot-check at close, later defects fix forward; `docs` = `doc` + consistency pass. Default tier = `kernel`. Off-spine improvements + data-tier remediation append `.agent/polish.md` (acceptance check + `pri` written at deferral); units stay spine work.
- MAIN's window buys: acceptance contract, batch verdicts on prepared decision points, implementation, divergence + finding rulings, decisive-gate reruns, commits, MAIN-retained files. Bulk payloads (failure logs, transcripts, long reports, green runs) route through a teammate digest w/ pointers; digests = browse context. Every report is two-tier — a verdict table (one row per deliverable unit: `id | verdict | finding ≤1 line | evidence pointer`) over detail sections keyed by row id; MAIN harvests the table + opens a section per row it rules on or acts from. Harvest is the dominant pre-implementation cost ⇒ the table is what holds it inside the window.
- Any artifact a later mode dispatches from is committed to `.agent/decisions/` — contracts (`m<m>u<u>-contract.md`), ruled tables (`-verdicts.json`, `-attack.json`), their `--check` patchers (`-rule-*.py`) + validators — outside the attached set, read on demand. `.scratch/` is gitignored + the Close order captures worktree content alone, so a `.scratch/` pointer is already dead in every clone and committing is what carries an artifact forward.
- MAIN-retained files = `.agent/roadmap.md`, `.agent/memory.md`, `.agent/polish.md`, `.agent/decisions/`, `.agent/archive/`, `CLAUDE.md`, command/skill files. A teammate returns a proposed delta inline in its final message; MAIN reviews it and applies the durable edit.
- Traffic terminates at MAIN: findings, oracle results, digests land in reports MAIN polls; MAIN alone dispatches follow-ups.
- Portfolio (`<role>-m<m>[u<u>][-<k>]`):
  - `map` = code/spec surface map + anchored normative checklist (`file:line` per obligation) + git archaeology (analog units; SHAs = checkable pointers). `res` = bounded question set + explicit WebSearch allowance + the `Authenticated web` route for authenticated/paywalled sources.
  - `spike` = one design alternative validated on real pipeline probes in its worktree; MAIN picks; the decision record enters the contract.
  - `test` = diff-blind on TWO counts audited separately: contract + normative docs + its OWN worktree's baseline, which the contract's git-object pins require reading, while the primary tree's `src/`/`tests/`/`docs/`, `git show main:` + `git diff main` stay unread — audit both counts over the transcript under a positive control listing the worktree's own paths. Each clause pins the PROPERTY, derived by AST or by running the named gate; one pinning the baseline's code shape (helper names, occurrence counts, assertion spellings) reddens correct code. MAIN owns the credential the brief cannot: run the delivered suite against the base SHA (`git worktree add --detach`, `PYTHONPATH=<baseline>/src`, import path verified as the baseline's) and against HEAD — red-at-baseline / green-at-HEAD, REPORTED never forced, since preservation obligations legitimately hold at baseline. Phase 1 `<NAME>-PREP-<i>`: enumerate edge inputs + divergent contract readings ⇒ MAIN batch-rules expected outcomes — the verdict table becomes probe corpus + contract clarifications. Phase 2 `<NAME>-DONE-<i>`: encode every verdict + own adversarial probes as the red suite MAIN implements against.
  - `orc` = reference implementation of the identical contract in its worktree — differential instrument: divergences vs MAIN = review targets, bytes stay evidence. Instruct it NOT to match MAIN's rulings: a divergent oracle BUILDS the branch other lenses only warn about, and agreement hides it.
  - `attack` (WORK-UNIT) = adversarial attack on the OPEN unit's contract + battery, delivering `m<m>u<u>-attack.json`; MAIN rules every row into the contract's numbered section through an idempotent `--check` patcher asserting the id set (`m3u5b-rule-attack.py` pattern), so a later row addition fails loudly instead of going unruled.
  - `mut` (WORK-UNIT) = mutation campaign over the unit's touched predicates from its OWN catalogue (`m<m>u<u>-mutants.json`), never the implementer's list, which certifies only the families its author already had in mind; MAIN replays it by unique anchor with a per-mutant liveness proof and a pristine control (memory carries the `__pycache__` + re-anchoring rules), so the kill list is a rerun rather than a judgment.
  - `prod` = validator-gated artifact production: before dispatch MAIN ships the contract's predicates as an EXECUTABLE validator + commits the seed it grades; the brief orders that validator LAST and forbids reporting done before it, and MAIN reruns it against the artifact instead of reading the number out of the report. `doc` = drafts from contract + shipped code; MAIN edits into place.
  - `diff` = cross-checks as committed scripts + outputs (credited by MAIN rerun): MAIN impl vs each oracle over the probe corpus (output-hash where deterministic), red suite × every impl.
  - `rev` + `rev2` (MILESTONE-REVIEW) = adversarial review of MAIN's diff on declared complementary lenses — correctness/spec + claim soundness + guarantee-vs-claim gaps + CLAUDE.md conformance | removal closure, where an obligation whose pin was deleted with the behavior keeps the gate green | determinism sweeps + re-ruling of the units' surviving mutants. A claimed defect ships as a red test in the reviewer's worktree, red pre-fix + green post-fix; judgment-only findings ⇒ council rule: ≥2 independent lenses confirm ⇒ accept; unique ⇒ MAIN validates by probe before acting.
  - `triage` = on-demand failure intake: full log → minimal repro + bisection + cause hypothesis; the repro's rerun is its own credential.
  - `audit` = claim replayer (MILESTONE-REVIEW). `scout` = next unit's probe/corpus surface. `gate` = standing gate-strength track (property tests, differential oracles, mutation automation) — each increment moves one MAIN judgment into the gate.
- Brief = role + scope + contract, COPIED into the worktree at dispatch (`cp` + `cmp` proving byte-identity) because a worktree based at an earlier SHA cannot see an uncommitted `.agent/` record and teammates correctly refuse a primary-tree read path + worktree path + base SHA = the commit MAIN implements onto, so a delivered suite runs against it + marker `<NAME>-DONE-<i>` + report delivered INLINE as the teammate's final assistant message with the marker as its last line — the subagent harness FORBIDS report/summary/findings `.md` files, so a brief naming a report PATH makes the agent choose between policy and brief and it withholds the marker; the committed artifact (table, suite, script) is the real deliverable, and MAIN materializes `.scratch/agents/<name>.md` itself where it needs the bytes addressable (memory carries the harvest recipe) + two-tier report shape + deliverable-unit total + batch size (global `CLAUDE.md` deliverable-first checkpointing) + validator command its output passes + every consumed upstream id/artifact (inlined or pathed; complete pointers = direct resolution) + questions/follow-ups route exclusively to MAIN (`SendMessage` to a peer silently resumes a stopped agent with its write allowlist live) + `read-and-conform-to` set: gates (project format/lint/type-check/test entry points + quality-gate command), oracles (test suite + corpus, benchmark/demo entry points), scope sources (roadmap, memory, project scope + spec docs) ⇒ teammate disagreement becomes a report for MAIN's ruling. Batch independent spawns in one block; dependent spawns form waves.
- Under abundant teammate capacity, fund `scout`, `gate`, post-acceptance fuzz/property campaigns that escalate on a find. Speculation yields provider capacity to the active wave; unit close stays speculation-independent. Each result distills into roadmap/gate at harvest or expires.
- Review contract (every review teammate, every mode; project `CLAUDE.md` review-termination rule): enumerate the check set from contract + normative docs + touched surface first — that set fixes the report's rows = the review's deliverable-unit total — then adjudicate it against MAIN's diff. Report = the filled table: `pass` + what was checked | `fail` + severity + `file:line` + divergence + breached predicate + impact + acceptance check, shipping a red test wherever one expresses it. An all-`pass` table completes the review. Observations outside the contract land in the report's register section, each with evidence pointer + acceptance check ⇒ MAIN appends the well-formed ones to `.agent/polish.md` unruled and the rest expire with the report. One reviewer per mode carries the project-CLAUDE.md-conformance lens — Authoring rules on every touched durable file + Engineering practices on code. MAIN's ruling on a row binds for the milestone; new evidence is what reopens it. MAIN applies accepted fixes itself and each closes on its acceptance check under MAIN's rerun; a judgment-dependent fix earns one re-review round scoped to its own row — fix diff vs that acceptance check, verdict `pass` | `fail` + evidence; a second `fail` on one row ⇒ MAIN rules and the ruling enters the contract.
- Roster at `.scratch/agents/roster.md` from first spawn (append via `tee -a … <<'EOF'`), one row per INSTANCE — name | worktree | transcript (`context-gauge -p <name>`; machine tool, `~/.local/bin`) | marker | watcher bg-task id | last gauge | flushed units (n/total) | status | report. Poll every teammate in one loop from it, writing gauge + flushed-unit count on every pass; retire a row's watcher in the same call that stops or supersedes its teammate.
- Hygiene follows the global `CLAUDE.md` `Subagents` protocol (scoping, marker polling, revive/death cadence, report-file confirmation, `TaskStop` at harvest). Project deltas: gauge = `context-gauge <name>`; successor = `<role>-m<m>u<u>-<k+1>` inheriting report + accepted findings + its predecessor's worktree, whose paths its brief names.
- Close order = global `CLAUDE.md` `Subagents`, run at every commit ending a wave; each mode's close bullet below adds only its own deltas, and the roster is the quiescence sweep's row set. Project delta: worktrees go, `wt/` BRANCHES STAY — they are the only refs keeping the recorded teammate SHAs resolvable for MILESTONE-REVIEW, and two refs cost nothing. A local-only ref never carries a ruling: restate its grounds as measured facts in the tracked record.
- Verification: MAIN reruns decisive gates and credits evidence tracing permitted real inputs. Campaign artifacts (matrices, kill lists, sweeps) = committed script + output, credited by rerun. Re-derive a teammate artifact before crediting it — a `.scratch/agents/` PASS from a pre-repair copy certifies the OLD state. Compaction-crossing checkpoint claims require source re-derivation before action.
- Context: per the project `CLAUDE.md` policy MAIN checkpoints (roster + state) before each compaction boundary and continues. WORK-UNIT records usage at every session close — MAIN gauges itself at each wave boundary and funds the next wave while the global `CLAUDE.md` reserve holds; at reserve it closes the SESSION on a checkpoint commit naming the next session's first action, and a unit spending more sessions than its budget records the overrun beside `main=` so PLANNING sizes against it. MILESTONE-REVIEW at reserve holds the milestone IMPLEMENTED and leaves its unadjudicated rows for the next MILESTONE-REVIEW session, keeping review debt inside dispatch; `.agent/polish.md` carries out-of-contract register entries alone.

PLANNING — split scope into milestones as needed; plan the next milestone.
- Read the prior milestone's commit range + recorded gauges (once a milestone closes its per-unit records live in the `.agent/archive/` record the roadmap stub names); for the first planned milestone read the scope-seed commit(s) the roadmap names. Size every unit in MAIN SESSIONS, bottom-up from the nearest analog's session record (`main=` per session on MAIN-implemented units, `impl=` on earlier delegated ones ≈ implementation load) and name what each session buys (`S1 measurement + rulings, S2 contract + implementation, S3 battery + closure`), then calibrate: multiply by the ratio measured on the nearest analog OF THE SAME SHAPE — never a milestone average, since every 1.00 is a unit sized against its own shape and every overrun is the first unit of a new one — which memory records as 1.00 for a repeat shape and up to 2.33 for an unprecedented one; record both figures as `est <raw> → <cal> sessions` and split at the unit's named seam where the calibrated figure exceeds the budget. Corrections live in the multiplier. A milestone with no recorded actuals runs its first unit as the calibration probe and re-sizes the rest from that measurement; a tier with no analog stays uncalibrated and says so. Entry cost is the term to cut before adding sessions: attached state + the ground-state read spend ~150K before the first gate stage runs. Judgment review is milestone-scoped: project its session count from the milestone's `kernel` unit count × the nearest analog's rows-per-unit, and record that projection in the roadmap so MILESTONE-REVIEW knows its own size.
- MAIN confirms each milestone precondition through project pipeline/tooling. Met ⇒ clear standing block + continue. Pending ⇒ record standing block + evidence; changed record ⇒ commit `roadmap (M<m> block): …`; stable record ⇒ read-only close.
- Wave 1 (one block): `map-m<m>` + parallel `res-m<m>-<i>`, one bounded question set each. Wave 2: `plan-m<m>` drafts the unit split from map + research, declaring every unit's `tier=kernel|data|docs` — milestone = MVP spine (shortest unit path to a consumable artifact; off-spine improvements → `.agent/polish.md`) — and tagging kernel/spec-critical units `oracle` (adds `orc` + the full campaign battery) + validator-gated artifact units `prod` (teammate-produced behind validators). Wave 3: `planrev-m<m>` attacks the draft (sizing realism vs recorded actuals, tier assignments — a data artifact under kernel battery = a sizing defect — dependency order, gate coverage, missed scope, parallelizability, CLAUDE.md conformance). MAIN arbitrates + writes the roadmap; planning holds sole sizing authority, so every unit ships as scoped.
- Sequence gate-independent prep first; mark a gated unit BLOCKED until its precondition is met.
- Close per Close order: set the milestone IN-PROGRESS (units enumerated), commit `roadmap (M<m> plan): …`.

WORK-UNIT.
- Read the last completed unit's commit(s), or the planning commit(s) for the milestone's first unit.
- Precondition transition: recheck BLOCKED first. Met ⇒ clear block, set OPEN, continue. Pending ⇒ retain BLOCKED; materially changed evidence ⇒ update + commit `roadmap (M<m>.<u> block): …`; stable evidence ⇒ read-only close. OPEN + pending ⇒ set BLOCKED, record condition/evidence, make the block commit, close.
- Wave 1 (one block): `map-m<m>u<u>`; material design fork (constructor/naming/spec surface) ⇒ `spike-m<m>u<u>-<alt>` per alternative. MAIN picks from spike evidence and writes the acceptance contract to `.agent/decisions/m<m>u<u>-contract.md` — numbered sections, testable predicates + invariant surfaces + a NUMBERED gate list every closure claim reruns from committed state + probe-corpus seed; every downstream artifact decides against it, and a gate added mid-unit invalidates those pins instead of strengthening them.
- Wave 2 (one block, contract copied into each worktree): `test-m<m>u<u>`; `attack-m<m>u<u>` against the contract + its battery; `orc-m<m>u<u>` on `oracle` units — dispatched beside MAIN's implementation, which is what makes it diff-blind; `prod-m<m>u<u>` for the unit's validator-gated artifacts.
- MAIN batch-rules the `test` phase-1 table; implementation starts once the phase-2 red suite sits in the primary tree and runs red. MAIN implements against it, harvesting each case as it drives it green (a disputed red ⇒ inspect, rule, correct suite or contract); failure logs + intermediate runs route through `triage-m<m>u<u>`.
- Suite green ⇒ `diff-m<m>u<u>` cross-checks + `mut-m<m>u<u>`'s catalogue, both credited by MAIN's own replay; MAIN rules each divergence with authorship knowledge — oracle consensus against MAIN's reading indicts the contract ⇒ correction lands in verdict table + red suite first, code second.
- Every session closes on its own `S<k> CHECKPOINT`/`S<k> DONE` roadmap record — what shipped, what the next session opens on, `harvest=` (MAIN's gauge as implementation starts; measures the entry cost) + `main=` (`context-gauge`, at close and at every compaction boundary) + `mate=` (`context-gauge <name>`, high-water across teammates), all `N% NK/240K` — and a commit; the session ends there.
- Close per Close order — the unit completes on contract predicates green under MAIN's rerun: rule every battery red as SUITE / CODE / CONTRACT defect and every attack row into the contract's numbered sections through their `--check` patchers, name the ruled tables + the `test`/`orc`/`diff`/`attack`/`mut` branch tips in the contract and point the roadmap's unit record at it, since those are MILESTONE-REVIEW's dispatch inputs; set the unit DONE with its `est → actual` session pair and — once all units are DONE — the milestone IMPLEMENTED; commit `<scope> (M<m>.<u>): …`.

MILESTONE-REVIEW — owns all judgment review.
- Read each taken unit's contract + the ruled tables and branch tips it names, plus that unit's commits. A resumed session reads the ledger first and takes the next unadjudicated units.
- Ledger `.agent/decisions/m<m>-review.json`, committed, one row per check-set row — unit | reviewer | row id | verdict | evidence | acceptance check — seeded whole before adjudication starts and written ONLY through an idempotent `--check` patcher (`m<m>-rule-review.py`, `m3u5b-rule-attack.py` pattern) that asserts the id set, derives its counters from final state and reports `no-op` on rerun; run it twice before trusting it once. Resume point = the first unruled row. Never in-window prose, which no later session can resume.
- One block, sized to MAIN's adjudication budget rather than to the unit count: per-unit reviewers (`kernel` = that unit's commits + touched surfaces, correctness/spec; `data`/`docs` = spot-check grade, sample + claim consistency alone), one cross-cutting reviewer (cross-unit integration; project-CLAUDE.md conformance incl. instruction/memory token-efficiency + obsolescence), one `audit-m<m>` claim replayer (re-derives every roadmap/docs claim for the milestone: full gate suite, reproduction result per recorded number, mismatches flagged). Each reviewer opens by enumerating its check set over its declared surface, then reports under the Review contract.
- MAIN validates + dedupes (council rule); `prod`-artifact batches go to one fix teammate per cohesive batch (locations + acceptance checks), each closed by MAIN's decisive-gate + acceptance-check rerun.
- A requirement-changing design reaches the user before any scope-source edit.
- Close per Close order. Rows open ⇒ commit the ledger, hold the milestone IMPLEMENTED, and the next session resumes. Every row adjudicated ⇒ set the milestone REVIEWED, move its unit detail + the ledger to a topical `.agent/archive/<record>.md` the roadmap stub names (project `CLAUDE.md` attached-state rule) leaving one roadmap summary — status, commit range, shipped surface, gauge band, archive pointer. Either way commit `<scope> (M<m> review): …`.

Commit convention — `<scope> (<trace>): <cause> → <fix>` per project `CLAUDE.md`, trace key in parens: unit `(M<m>.<u>)`, block `(M<m> block)` / `(M<m>.<u> block)`, plan `(M<m> plan)`, review `(M<m> review)`. Grep a milestone's history: `git log --grep "(M<m>[. ]"`.
