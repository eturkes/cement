# Open WebUI example law (0.12.3, paste-in deployment)

Rulings = `.agent/spec.md` `Decisions` "Open WebUI deployment"; live record = `.agent/decisions/owui-live-e2e.md`.

- Sources `examples/open_webui/cement_*.py` (importable with an installed `cement_runtime` + a stub `pydantic`, `tests/test_open_webui_example.py` `_load`) → `uv run python examples/open_webui/generate.py` → `paste-in/<same name>.py`. Never hand-edit `paste-in/`: the freshness test reds a stale file. Generated layout = the source's head imports → embedded `_CEMENT_SOURCES` (`src/cement_runtime/*.py` minus `cli` + `__main__`) + a meta-path importer for `_cement_runtime_<sha256[:16]>` → bindings replacing the `cement_runtime` imports → the source body. Generator refusals: `cement_runtime` imports must CLOSE the source's import block (E402 + isort stay clean with no ruff config change); no `'''`; none of `from utils|apps|main|config` anywhere in a source or the library — Open WebUI's `replace_imports` rewrites those substrings in pasted code on every save. Every file checks ITS OWN embedded sources against `_CEMENT_DIGEST` on every load, also when another copy already loaded the package (an edited later copy would otherwise reuse the clean package); the check catches an accidental edit, it is not a signature. Import shapes the bindings cannot reproduce are refused: `import cement_runtime.x` without `as`, a statement mixing `cement_runtime` with other modules, any non-import statement between the first and the last library import.
- `LOADER` imports `importlib.machinery` before installing its finder: `find_spec` imports it lazily, which recursed under `python -I -S` once no embedding source had preloaded it (`examples/nucllei/ext/bin/cement`; `tests.test_nucllei_example` N7 `test_n7_the_command_runs_on_the_standard_library_alone` fired with `RecursionError` after the nucllei source dropped `dataclasses` → `inspect`).
- Item ids: chat tool `cement`, learning tool `cement_learning`, filter `cement_filter`, action `cement_switch` (`cement_admin.py`), skill `cement-learn`. Users need READ access to `cement`: `get_tools` (`utils/tools.py`) silently drops a tool the user cannot read.
- Valve `operations` = one line per operation, `name: description` (names alone, comma list included, still parse). Every source carries its own `_operations` (paste-ins share no code); the copies stay AST-identical (guard below).
- Writers: proposals ← the filter alone; reviews / supersessions / revocations / projection / promotion ← the learning tool alone (reviewer + actor `learning-pass`, role `admin` checked per call); registration + switch ← the action alone (it pages every version receipt, so any earlier version stays pinnable and its number holds) (role `admin`, a value the select OFFERED, confirmation `True`; actor `open-webui:<user id>` because Cement names refuse `@`). No model-callable function reaches `set_switch`, `register_operation` or `revise_operation` (AST pin over `cement_learning.py` + `src/cement_runtime/learning.py`).
- Learning tool division (live-run finding, record § Learning passes): the model judges projectability + each case's merged output; the tool runs `cement_runtime.learning` (shared with the nucllei command + the CLI), which derives the program (`projection.structure`, one layout per distinct title + structure, inputs must hold exactly one text field) and does the review/supersede bookkeeping (`merge_case` refuses ids of more than one case and repeated ids, reads each example's output from the case itself — never a paged `System.examples` read — and, because every library write commits alone, returns a refusal after a partial write (the library raises `MergeInterruptedError`) with `completed` = the writes whose calls returned; the raising write may also have committed ⇒ recovery = a fresh `cases` read, never a retry). `draft_program` requires every input to hold one text field with a string value; `learning.raw_inputs` takes active examples and pending proposals of the CURRENT revision only. The tool maps library results to its JSON (lists via `_json_shaped`; English `_NOT_PUBLISHED` reasons) and adds nothing else. gpt-6-luna dropped the mechanical steps when the skill asked it to write programs + per-id reviews.
- Open WebUI 0.12.3, measured live: built-in `search_tools` (the model finds tools by query first); a model-attached skill (`meta.skillIds`) is only LISTED unless `meta.builtinTools.skills` is false, so the learning model turns it off (UI: Builtin Tools → Skills); action dialog = `__event_call__` `{"type": "input", "data": {"type": "select", "options": [{label, value}]}}` → the chosen value, `confirmation` → `True`, cancel → `False`; the action button renders outside `.chat-assistant` (`button[aria-label='Cement switch']`); a tool's parameter schema is stored at save, its description re-read per request; `meta.toolIds` = the UI's default selection (REST callers pass `tool_ids`), while `filterIds` / `skillIds` / `actionIds` apply server-side; `__user__`, `__chat_id__`, `__model__` reach a function by signature.
- Local regimen: `uv run python examples/open_webui/local.py setup` (installs `examples/open_webui/local-requirements.txt` with `--require-hashes`: universal, Python `PYTHON`, every package hash-pinned; an `OPEN_WEBUI` or `PYTHON` bump reruns the command in its header; `test_p128_*` in `tests/test_open_webui_local.py` pin the argv + the lock's target, Python and hashes), then `OPENAI_API_KEY=<key> … serve --base-url <endpoint>/v1 --model <id> [--fresh]`, `… provision --model <id>` after regenerating; state `.open-webui/` (gitignored; venv, `data/`, `data/cement/ledger.db`). The instance binds 127.0.0.1 behind a login (`WEBUI_AUTH` on, `ENABLE_SIGNUP` off ⇒ the launcher's first signup = the one admin) with `CORS_ALLOW_ORIGIN` = its own two origins (`127.0.0.1` + `localhost` at its port; Socket.IO reads the same list): no-login 0.12.3 hands any caller an admin token, its default CORS `*` lets any web page read it, and an admin token runs code (`tools/create` execs the pasted source); CORS alone leaves DNS rebinding, since 0.12.3 has no Host allowlist. Password = `<dir>/admin-password` (0600, `_kept_token`); `_sign_in` replaces a no-login instance's `admin`/`admin` on its first start (pinned by the `test_s1_*` frames in `tests/test_open_webui_local.py`). `serve` stops the server's session on Ctrl-C or SIGTERM, with SIGKILL after 30 s (`_stop`). Wiring = `local.py` `plan()` (pinned by `tests/test_open_webui_local.py`). The key travels by environment only. Drivers of the live run stay scratch.
