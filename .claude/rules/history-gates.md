# History-walking gates (D28) + composition (D19)

- D28 (`tests/test_migration_battery.py`) replays the full suite at EVERY revision in `99f260a^..HEAD` (`D28_START`, owner-ruled p123: D28 runs on the latest Python, and the 77 revisions after `6fb4d92` and before `99f260a` pin 3.13's argparse wording — each holds a green 3.13 verdict, CI run 39962224658) touching `tests/`, `examples/` or `m3u6a1-surgery.py` ⇒ every commit touching those paths must be gate-green (adapts `CLAUDE.md` `Session flow` Checkpointing: red work never lands on `main`). Red-to-green work rides `impl/<unit>`, tip tagged `archive/m<m>u<u>-impl[-<k>]` (`-<k>` = a different branch of one unit = a different history), and squashes into main as ONE green commit; a code seed uses `skipTest`, never `fail`.
- Verdict cache (p78, equal-strength speed-up): D28 serves a revision from a GREEN verdict for its content key (`_d28_content_key` = replayed tree id + inner argv `D28_INNER` + `sys.version` + implementation + platform + `sqlite3.sqlite_version` + the primary `uv.lock` sha256), else replays it; `_d28_record` runs only after both replay assertions (pinned by `D28VerdictCacheTests`) ⇒ red is never recorded and a red revision replays on EVERY run. Store = `<git-common-dir>/cement-d28-verdicts/` (per clone, shared by worktrees, tracked by none); a damaged or foreign record replays. `sys.version` carries the interpreter's build date ⇒ a clone without this store, or a different interpreter build, replays cold: the CI gate's full leg restores `main`'s store (`ops.md` Template rulings (5)), a local full gate runs in the clone that holds it (machine commands → `CLAUDE.local.md`). stderr line `D28: N revisions, R replayed, S from green verdicts` = what ran. An amend that keeps the tree = a hit; a clean clone replays all until restored (CI: `actions/cache`). Cold rerun = `rm -rf "$(git rev-parse --git-common-dir)/cement-d28-verdicts"`. Changing what an inner run must prove (argv, a new assertion over its output) = change `D28_INNER` or `D28_VERDICT_FORMAT` so old verdicts stop matching.
- Launch the gate with SIGINT at SIG_DFL: a non-interactive shell's `&` job hands down SIG_IGN, which bash cannot reset (Python can: `signal.signal(…, SIG_DFL)` over SIGINT + SIGPIPE + SIGXFSZ — the last two Python's own startup ignores, and an exec hands that down — then `os.execvp`), and revisions `21b7463` up to the p25 probe repair carry an interrupt probe that then exits 4 ⇒ a cold D28 replay of them reds.
- On a red branch each ADDITIONAL commit touching those paths enters the replay range and adds exactly one D28 break ⇒ a rising D28 count is arithmetic, not regression: compare the failing test ID SET, nested replay sets included, never the count. The squash collapses the range to one revision.
- D28 is the ONLY gate grading history, and splitting the suite to bound wall time hides it (`discover` minus `tests/test_migration_battery.py` plus that module minus `test_d28` = every test but D28, green with history unexercised). A unit closes on ONE full `discover` with `test_d28` INCLUDED, run on `main` from the squash commit itself; a split rerun names what it omits. A red-to-green branch cannot pass it ⇒ the squash is the first answerable state, and a defect it finds is repaired by AMENDING that commit — a fix on top leaves the red revision in range forever, since D28 grades committed trees.
- D28 unlinks `tests/test_migration_battery.py` from each checkout before the inner run (instrument, not subject; keeping it nests D28 per revision past the timeout). Four frames in `tests/test_lifecycle_removal_battery.py` READ that file (L23 imports it for the census pin `test_d23_examples_hospital_ocr_readme_md_208_and_216_name_the`; L23's body freeze + L26 read its bytes; L29 counts pins over a working-tree scan) ⇒ the two instruments are mutually exclusive. Pairing: D28 exports `CEMENT_D28_INNER_REPLAY=1` (reaches every inner process via `_environment`'s `os.environ` copy) and `instrument_pruned()` narrows those frames to the checkout (15 pins → 14, `opening` 14 → 13, L26 targets 4 → 3, L30 skips; `_freezes()` stays 4). The helper checks BOTH ways — announced ⇔ absent, else `AssertionError` — because an `is_file()` test alone lets a real deletion narrow the frames instead of reddening them. Seeds → `gate-checks.md`.
- `_detached_worktree` (every migration-battery checkout) lives in a run-scoped directory `<git-common-dir>/cement-test-worktrees/<pid>-*` (outside every working tree, so no tree census sees it); a run killed before its `finally` leaves that directory + its registration, and the next `_detached_worktree` call or `uv run python -m tests.test_migration_battery --clean` removes every run directory whose PID is gone (p55, `WorktreeOrphanTests`).
- `m3u6a2-tripwires.json` keys each pin + freeze on `<file>:<test name>` + span length and each prose hit on its line TEXT (p63), so an edit above a censused frame or elsewhere in a document leaves `uv run python .agent/decisions/m3u6a2-tripwires.py` green; renaming a censused test, resizing its span or rewording a hit line reds it (`DRIFT`) ⇒ rerun `--emit` and review the diff (the provenance-only `head` line always moves).
