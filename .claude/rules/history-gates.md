# History-walking gates (D28) + composition (D19)

- D28 (`tests/test_migration_battery.py`) replays the full suite at EVERY revision in `6fb4d92..HEAD` touching `tests/`, `examples/` or `m3u6a1-surgery.py` ⇒ every commit touching those paths must be gate-green (adapts `CLAUDE.md` `Session flow` Checkpointing: red work never lands on `main`). Red-to-green work rides `impl/<unit>`, tip tagged `archive/m<m>u<u>-impl[-<k>]` (`-<k>` = a different branch of one unit = a different history), and squashes into main as ONE green commit; a code seed uses `skipTest`, never `fail`.
- On a red branch each ADDITIONAL commit touching those paths enters the replay range and adds exactly one D28 break ⇒ a rising D28 count is arithmetic, not regression: compare the failing test ID SET, nested replay sets included, never the count. The squash collapses the range to one revision.
- D28 is the ONLY gate grading history, and splitting the suite to bound wall time hides it (`discover` minus `tests/test_migration_battery.py` plus that module minus `test_d28` = 1000 + 30 of 1031, green with history unexercised). A unit closes on ONE full `discover` with `test_d28` INCLUDED, run on `main` from the squash commit itself; a split rerun names what it omits. A red-to-green branch cannot pass it ⇒ the squash is the first answerable state, and a defect it finds is repaired by AMENDING that commit — a fix on top leaves the red revision in range forever, since D28 grades committed trees.
- D28 unlinks `tests/test_migration_battery.py` from each checkout before the inner run (instrument, not subject; keeping it nests D28 per revision past the timeout). Four frames in `tests/test_lifecycle_removal_battery.py` READ that file (L23 imports it for the census pin at `tests/test_migration_battery.py:1426`; L23's body freeze + L26 read its bytes; L29 counts pins over a working-tree scan) ⇒ the two instruments are mutually exclusive. Pairing: D28 exports `CEMENT_D28_INNER_REPLAY=1` (reaches every inner process via `_environment`'s `os.environ` copy) and `instrument_pruned()` narrows those frames to the checkout (15 pins → 14, `opening` 14 → 13, L26 targets 4 → 3, L30 skips; `_freezes()` stays 4). The helper checks BOTH ways — announced ⇔ absent, else `AssertionError` — because an `is_file()` test alone lets a real deletion narrow the frames instead of reddening them. Seeds → `gate-checks.md`.
- An edit ABOVE the census pin in `test_migration_battery.py` drifts its locus from `m3u6a2-tripwires.json` ⇒ rerun `uv run python .agent/decisions/m3u6a2-tripwires.py --emit` and expect a two-line diff (the locus + the provenance-only `head`, which no test asserts and every amend restales); p63 queues the fix.
